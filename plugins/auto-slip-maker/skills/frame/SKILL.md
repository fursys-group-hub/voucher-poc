# 틀 잡기

> 단계를 확정하기 위한 초안이다. 최종 형태(로컬 파일 / 배포되는 앱)가 정해지지 않아 제약은 최소로 두고, 해 보면서 필요한 것만 추가한다.

## 목적

값 채우기에 필요한 재료 세 가지를 모은다: **자동화 목적**, **참고할 지난 전표**, **원천 데이터 파일 주소**.
분석하거나 정하지 않는다. 항목별 분석과 결정은 다음 단계(값 채우기)에서 한다.

## 하는 일

1. **자동화 목적 받기**
    - 이렇게 묻는다:
      > 어떤 전표를 자동화하고 싶으세요? 무엇 때문에 쓰는 전표인지 한두 문장으로 알려 주세요. (예: 사무실 임차료를 매달 부서별로 나눠 비용 처리)
    - 답을 한 줄로 정리해 확인받는다.
    - 이 목적이 자동화 요청 하나의 범위다. 정의서 맨 앞에 들어가고, 정의서를 등록할 때 생성 요청을 검토하는 데 쓴다.
2. **지난 전표 조회**
    - 목적에서 적요에 들어갈 만한 단어를 뽑아 제안한다.
      > 지난 전표를 찾아볼게요. 적요에 "○○"가 들어간 전표로 찾아볼까요? 다른 단어나 **전표번호**로 찾으셔도 돼요.
    - 답을 받으면 전표 조회 API로 찾는다 → [전표 조회](../../api/전표조회.md)
    - 찾은 전표를 보여 주고, 같은 전표로 매달 쓴 것들을 고르게 한다.
3. **원천 데이터 파일 받기**
    - 반복 전표는 대부분 매달 그 데이터대로 쓰는 원천 데이터 파일(예: 엑셀)이 있다. 그래서 있다고 보고 묻는다:
      > 이 전표를 작성하는 데 필요한 데이터가 저장되어 있는 **파일 주소**를 보내 주세요. (예: D:\전표자료\비용내역_202610.xlsx)
      > 매달 바뀌는 값을 직접 입력하실 거라면 "없음"이라고 해 주세요.
    - 주소를 받으면 파일이 열리는지만 확인한다.
4. **정리**
    - 작업 폴더에 `참고자료.md` 로 남긴다: 목적, 고른 전표번호, 원천 데이터 파일 주소(없으면 "없음"). 형식은 해 보면서 정한다.
    - 값 채우기(`auto-slip-maker:fill`)로 넘긴다.

## 현업에게 묻는 것

- 자동화 목적 (무엇 때문에 쓰는 전표인지)
- 찾을 전표 (적요 또는 전표번호)
- 참고할 전표 고르기
- 원천 데이터 파일 주소

## 필요한 API

- API는 이 명령 하나로만 부른다: `python -X utf8 "${CLAUDE_PLUGIN_ROOT}/api/call.py" <짧은 경로> <요청 파일>`

- **확정**: 전표 조회 → [api/전표조회.md](../../api/전표조회.md)

## 대화 원칙

- 한글, 쉬운 말로 한다. 한 번에 하나씩 묻는다.
- 코드가 있는 값(법인, 부서, 계정 등)은 이름 뒤에 코드를 괄호로 함께 쓴다 (예: ○○ (코드)). 이름이 비슷한 값이 있어도 현업이 코드로 확인할 수 있다.
- 명령을 실행할 때 붙이는 설명은 현업이 알아볼 수 있는 쉬운 한국어로 쓴다 (예: "지난 전표를 가져와요", "거래처 목록을 조회해요").
- 플러그인 안내 파일은 `cat` 같은 명령 대신 읽기 도구로 읽는다.
