# 시작

> 단계를 확정하기 위한 초안이다. 최종 형태(로컬 파일 / 배포되는 앱)가 정해지지 않아 제약은 최소로 두고, 해 보면서 필요한 것만 추가한다.

## 목적

처음 쓰는 현업에게 무엇을 하는지 안내하고, 쓸 준비가 됐는지 확인한 뒤 틀 잡기로 넘긴다.

## 하는 일

1. **처음 안내**
    - 아래 문구를 **그대로** 보여 준다. 말을 바꾸거나 더하지 않는다.
      > **반복 전표 자동화, 이렇게 진행됩니다**
      >
      > 1. **틀 잡기**: 전표를 만들기 위해 먼저 틀을 잡아요. 지난 전표와 매달 받는 파일을 보면서 저와 대화로 정해요.
      > 2. **정의서·설명서**: 대화로 틀을 잡는 동안 정의서와 설명서가 자동으로 만들어져요.
      >     - 정의서: 전표 생성 요청이 정해진 대로인지 검토하는 기준이에요.
      >     - 설명서: 전표의 값을 어디서 가져오는지 적은 문서예요.
      > 3. **등록·승인**: 정의서를 등록 API로 등록하고 경영정보시스템 개발팀이 승인하면, 그때부터 전표 생성 API를 쓸 수 있어요.
2. **준비 확인**
    - 개발 환경: 매달 프로그램을 돌릴 도구(Python 등)가 있는지 확인한다.
    - 설정 파일: `python -X utf8 "${CLAUDE_PLUGIN_ROOT}/api/setup.py"` 를 실행한다.
        - 설정 파일(서버 주소, 인증키, 호출 식별자, 작성자 ID)이 없으면 빈 칸으로 만들고, 빈 칸이 있으면 메모장으로 연다. 칸마다 채워졌는지만 알려 준다.
        - 빈 칸이 있으면 이렇게 안내하고 기다린다. 메모장이 열리지 않았으면 결과에 나온 파일 주소도 함께 알려 준다.
          > 메모장에 열린 설정 파일에서 빈 칸의 `=` 뒤에 값을 넣고 저장해 주세요. 서버 주소, 인증키, 호출 식별자는 경영정보시스템 개발팀에서 받은 값이고, 작성자 ID는 본인 account 로그인 ID예요. 저장하셨으면 알려 주세요.
        - 저장했다고 하면 다시 실행한다. 모두 채워지면 넘어간다.
3. **다음 스킬**: 틀 잡기(`auto-slip-maker:frame`)로 넘긴다.

## 현업에게 묻는 것

- 없음. 확인에 실패했을 때만 무엇이 없는지 안내한다.

## 필요한 API (후보)

- API 키 확인: 키가 유효한지, 사용 기간, 권한이 있는 법인 → 인증 쪽이라 이번 API 개발 범위에서는 빠진다.
- 플러그인 버전 확인

## 대화 원칙

- 한글, 쉬운 말로 한다.
- API 키는 채팅으로 받지 않는다.
- 명령을 실행할 때 붙이는 설명은 현업이 알아볼 수 있는 쉬운 한국어로 쓴다 (예: "지난 전표를 가져와요", "거래처 목록을 조회해요").
- 플러그인 안내 파일은 `cat` 같은 명령 대신 읽기 도구로 읽는다.
