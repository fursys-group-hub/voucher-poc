# 값 채우기

> 단계를 확정하기 위한 초안이다. 최종 형태(로컬 파일 / 배포되는 앱)가 정해지지 않아 제약은 최소로 두고, 해 보면서 필요한 것만 추가한다.

## 목적

전표의 항목마다 **값을 어디에서 가져올지** 정해 전표 틀을 완성한다. 매달 프로그램은 이 틀대로 원천 데이터 파일을 읽어 전표를 만든다.

정한 내용으로 **정의서**도 만든다. 정의서는 서버가 매달 생성 요청을 검사하는 기준이다 → [api/정의서.md](../../api/정의서.md)

## 가져올 곳

항목마다 값을 가져올 곳을 정한다. 아래 표는 자주 쓰는 **예시**다.
- 추천이 아니라고 하면, 이 표에서 그 항목에 맞는 것을 예시로 보여 주고 예시에 없는 방법도 말해 달라고 한다.
- 현업이 말한 방법은 표에 없어도 그대로 받아 적고, 그 방법에 맞춰 이어서 묻는다.

| 가져올 곳 | 뜻 | 이어서 묻는 것 |
| --- | --- | --- |
| 원천 데이터 파일 | 매달 받는 파일의 값 | 시트·열(·행). 지난 전표 값을 파일에서 찾으면 그 위치를 추천하고, 못 찾으면 어느 칸인지 묻는다 |
| 계산 | 다른 값으로 계산한 값 (합계, 비율 등) | 무엇으로 어떻게 계산하는지 |
| 고정 | 매달 같은 값 | 어떤 값인지 (보통 지난 전표 값) |
| 자동 | 실행하는 날·달에 따라 정해지는 값 (날짜, 년·월 등) | 어떤 규칙인지 (예: 그달 말일) |
| 매달 직접 입력 | 매달 실행할 때 현업이 글자로 넣는 값 | - |
| 매달 조회해서 선택 | 매달 실행할 때 API로 목록을 조회해 현업이 고르는 값 (거래처 등 코드 값) | 무엇으로 찾을지 (예: 이름 일부) |
| 비워 둠 | 매달 값을 넣지 않는 칸 (지난 전표에서도 비어 있던 칸) | - |
| 기타 | 위에 없는 방법 | 현업이 말한 방법 그대로 적는다 |

## 하는 일

1. **참고 자료 읽기**
    - 작업 폴더의 `참고자료.md` 를 읽고, 거기 적힌 전표들을 전표 조회 API로 가져오고, 원천 데이터 파일을 연다.
    - `참고자료.md` 가 없으면 틀 잡기(`/auto-slip-maker:start`)부터 하라고 안내하고 멈춘다.
    - 파일 내용이나 전표와 어떻게 맞는지를 미리 늘어놓지 않는다. **그 항목에 필요할 때만** 쓴다.
2. **정할 항목 안내**
    - 시작할 때 앞으로 정할 항목을 목록으로 먼저 보여 준다.
      > 지난 전표와 보내 주신 파일을 보면서, 앞으로 매달 전표를 자동으로 만들 규칙을 함께 만들어 갈게요.
      > **전표 전체** — 이 전표가 어느 회사·부서의, 언제, 무엇에 대한 전표인지 정해요.
      > 1. 법인 2. 작성부서 3. 전표일자 4. 적요
      >
      > **행별** — 전표의 줄마다 어떤 계정으로, 무엇을 적는지 정해요.
      > 5. 계정 6. 행 유형마다 금액·관리항목·코스트센터
    - 항목을 물을 때마다 맨 위에 **지금까지 정한 것**을 한 줄씩 보여 주고, 그 아래에 몇 번째 항목인지 쓴다.
        - 정한 항목만, "항목 → 정한 값 · 방법" 한 줄로 짧게 쓴다. 코드가 있는 값은 이름 뒤에 코드를 괄호로 붙인다.
        - 6에서는 끝난 행 유형을 한 줄씩 더한다 (계정·차대 → 금액·관리항목·코스트센터를 정한 방법).
      > **지금까지 정한 것**
      > - 법인 → ○○ (○○○○) · 파일의 ○○ 부분
      > - 작성부서 → ○○ (○○○○) · 지난 전표와 같음
      > - 전표일자 → 원천 파일 달의 말일
      > - 적요 → "○○ ({년}년 {월}월)"
      >
      > **5/6 계정** — …
3. **하나씩 정하기**
    - 안내한 순서대로 하나씩 정한다. 항목마다 아래 **설명**을 먼저 보여 주고, 지난 전표와 파일을 보고 가져올 곳을 추천한 뒤 확인받는다.
    - **전표 전체**
        1. **법인** — "이 전표를 어느 법인으로 작성되는지 정해요. 파일에 여러 회사 데이터가 있으면 회사마다 전표가 한 장씩 만들어지고, 한 장씩 차례대로 정해요."
            - [api/법인.md](../../api/법인.md)의 법인 목록을 번호와 함께 보여 주고, 여러 개를 고를 수 있게 묻는다. 지난 전표의 법인과 파일에 이름이 있는 법인을 추천한다.
            - 고른 법인마다 파일에서 그 법인 부분이 어디인지 정한다.
            - 법인이 여러 개면 전표 한 장(법인 하나)씩 1~6을 끝까지 정한 뒤 다음 법인으로 넘어간다.
            - 다음 법인의 지난 전표가 쓰는 계정(줄 구성)이 앞 법인과 다르면, 이 요청에서 정하지 않고 따로 자동화 요청으로 하자고 안내한다. 목적이 같아도 구성이 다르면 따로 한다.
        2. **작성부서** — "이 전표를 쓰는 부서를 정해요. 지난 전표와 같은 부서를 추천드리고, 다른 부서로 바꾸시려면 쓸 수 있는 부서 목록을 보여 드려요."
            - 지난 전표의 작성부서를 추천하고 확인받는다. 코드도 지난 전표 값을 그대로 쓴다 (전표를 만들 때 서버가 다시 확인한다).
            - 다른 부서를 쓰겠다고 하면 [작성부서 조회 API](../../api/작성부서.md)로 이 법인에서 쓸 수 있는 부서 목록을 보여 주고 고르게 한다. 사용 중지 부서는 고를 수 없다고 알린다.
        3. **전표일자** — "전표에 찍히는 날짜예요. 매달 어떤 날로 할지 정해요."
            - 어떻게 정할지 예시를 보여 주며 묻는다. 예: 작성 날짜(전표를 만드는 날), 고정 일자(매달 말일, 25일 등), 원천 파일 날짜, 매번 입력. 예시에 없는 방법도 말해 달라고 한다.
            - 지난 전표 날짜를 보고 하나를 추천한다.
            - 고정 일자면 며칠인지와 어느 달 기준인지(전표를 만드는 달 / 파일의 달), 원천 파일 날짜면 파일의 어느 칸인지 이어서 묻는다.
        4. **적요** — "회계 거래가 무엇 때문에 발생했는지 간단하게 설명하는 내용이에요. 매달 바뀌는 부분(년·월 등)만 정하면 나머지는 그대로 써요."
            - 지난 전표의 적요를 보여 주고, 고정 부분과 바뀌는 부분을 나눈 틀을 추천한다.
            - 바뀌는 부분마다 어디서 가져올지 정한다 (전표일자와 적요의 월이 다를 수 있다).
            - 지난 전표에서 계정마다 적요가 달랐으면 계정마다 다르게 쓸지 묻는다. 다르게 하면 6. 행 유형마다 정할 때 함께 정한다. 모두 같았으면 묻지 않고 모든 줄에 같은 틀을 쓴다.
    - **행별**
        5. **계정** — "지난 전표의 줄을 바탕으로, 매달 어떤 계정으로 몇 줄이 생기는지 정해요."
            - 복사등록처럼 지난 전표들의 줄에서 시작한다. 계정·차대(차변·대변)가 같은 줄을 한 **행 유형**으로 묶어 표로 보여 주고, 행 유형마다 생성 규칙을 추측해 확인받는다.
                > | 계정 | 차대 | 지난 전표 | 생성 규칙 추측 | 매달 |
                > | --- | --- | --- | --- | --- |
                > | ○○ | 차변 | n줄 (모든 전표) | 파일의 ○○마다 한 줄씩 | 꼭 생겨요 |
                > | ○○ | 차변 | 1줄 (모든 전표) | 파일의 ○○ 중 △△인 행마다 한 줄씩 | 없는 달도 있어요 |
                > | ○○ | 대변 | 1줄 (모든 전표) | 늘 한 줄, 금액은 차변 합계 | 꼭 생겨요 |
                > | ○○ | 차변 | 1줄 (일부 전표) | 규칙이 없는 예외인 것 같아요 | - |
            - 생성 규칙 추측은 보통 아래와 같은 모양이다. 맞지 않으면 보이는 대로 적는다.
                - 파일 행마다 한 줄 (파일 행이 여러 계정으로 나뉘면 나누는 기준도 적는다)
                - 파일 값으로 한 줄
                - 다른 줄로 계산한 한 줄
                - 매달 같은 줄
            - **매달** 칸은 이 행 유형이 매달 꼭 생기는지(정의서의 `생성`: 매번), 없는 달도 있는지(`선택`)다.
                - 지난 전표 모두에 있었고 파일 내용과 관계없이 생기는 줄이면 "꼭 생겨요"로 추측한다.
                - 일부 전표에만 있었거나 파일 행에 따라 없을 수 있으면 "없는 달도 있어요"로 추측한다.
            - 예외라서 매달 만들지 않기로 한 행 유형은 정의서에 넣지 않는다.
            - 규칙을 찾지 못한 행 유형은 "규칙이 없는 예외인 것 같아요"라고 적고, 왜 그렇게 썼는지 묻는다.
            - 현업이 아니라고 한 행 유형만 따로 묻는다. 기준에 필요한 정보가 파일에 없으면 어디서 알 수 있는지 묻는다.
            - 기준으로 정할 수 없는 파일 행(예: 처음 보는 행)이 나오면, 매달 프로그램은 그 전표를 만들지 않고 알린다.
        6. **행 유형마다 정하기** — "앞에서 정한 행 유형마다 들어가서 금액, 관리항목, 코스트센터를 정해요. 지난 전표를 보고 추천드릴 테니 확인해 주세요."
            - 5에서 확정한 행 유형(계정·차대)마다 차례로 들어가, 6-1~6-3을 하나씩 추천하고 확인받는다. 관리항목과 코스트센터는 계정에 따라 정해지고, 한 행 유형 안의 줄들은 규칙이 같기 때문이다.
            - **6-1. 금액** — "줄마다 금액을 어떻게 정할지 정해요."
                - 5의 생성 규칙대로 가져올 곳을 추천하고 확인받는다.
                - 아니라고 하면 위 **가져올 곳** 표에서 합리적인 선택지들을 묻는다.
            - **6-2. 관리항목** — "계정마다 함께 적는 추가 정보예요 (예: 거래처, 증빙). 지난 전표에 넣은 값을 보여 드리고, 매달 어디서 가져올지 정해요."
                - 관리항목마다 지난 전표 값이 매달 같은지 본다. 같았던 값은 고정으로 표 하나에 모아 한 번에 확인받고, 달랐던 값만 따로 묻는다.
                - 고정을 확인받을 때 이렇게 함께 묻는다.
                    > 이 값들이 바뀐 적이 있거나, 앞으로 바뀔 수 있나요? 고정으로 정한 값은 정의서에 들어가서, 매달 이 값이 아니면 전표가 만들어지지 않아요.
                    - 바뀔 수 있다고 한 값은 달라지는 값으로 정한다.
                - 달라지는 값은 계정과목 조회 API의 `input_type`에 따라 정하는 방법이 다르다.
                    - `text` (글자를 치는 값): 원천 데이터 파일 / 계산 / 매달 직접 입력 중에서 정한다.
                    - `select` (목록에서 고르는 값): 파일에 그 값의 이름이 적혀 있으면(예: 거래처명 열) 매달 그 이름으로 API에서 코드를 찾는다. 찾은 결과가 0건이거나 여러 건이면 매달 프로그램은 그 전표를 만들지 않고 알린다. 파일에 없으면 매달 조회해서 선택으로 정한다.
                    - `partner`: 거래처를 고르면 함께 정해지니 따로 묻지 않는다.
                    - `blocked`, `unsupported`: 자동으로 채울 수 없다고 알리고 "필요한 API"로 적는다.
                - 고정으로 정한 코드 값도 지금 쓸 수 있는지 관리항목 값 조회 API로 확인한다.
            - **6-3. 코스트센터** — "선택하신 계정 유형은 코스트센터를 선택해야 해요. 비용이 어느 부서 몫인지 정해요."
                - 코스트센터를 쓰지 않는 계정(계정과목 조회 API의 `yn_costcenter` = `N`)은 묻지 않는다. 화면처럼 작성부서의 기본 코스트센터가 들어가니 "작성부서를 따라 정해짐"으로 기록한다.
                - 지난 전표 값과 생성 규칙을 보고 가져올 곳을 추천하고 확인받는다.
                    - 매달 같으면: 지난 전표의 코스트센터를 그대로 쓴다. 지금도 쓰는 코스트센터인지 코스트센터 조회 API로 확인한다.
                    - 줄마다 달라지면 (예: 파일 행마다 한 줄): 파일의 어느 칸에 부서 이름이 있는지 정한다. 매달 그 이름과 정확히 같은 코스트센터를 API로 찾고, 없거나 여러 개면 매달 프로그램은 그 전표를 만들지 않고 알린다.
                    - 이번 달 파일의 이름으로 미리 찾아 보고, 못 찾은 이름이 있으면 바로 현업에게 보여 준다.
                - 행 유형이 판관·제조 계정으로 나뉘면, 코스트센터의 원가구분(A 판관, B 제조)과 계정이 맞는지 확인한다.
            - 통화·환율은 외화 계정일 때만 묻는다. 적요를 계정마다 다르게 쓰기로 했으면 여기서 함께 정한다.
    - 작성자·손익센터·전표유형은 묻지 않는다 (ID나 코스트센터를 따라 정해짐).
    - 결정이 필요한 것은 묶어서 묻지 않는다.
4. **정리**
    - 정한 내용을 표로 보여 주고 확인받는다.
        - 전표 전체: 항목 · 가져올 곳 · 이번 달 파일로 본 예시
        - 행 유형: 계정 · 차대 · 매달 · 생성 규칙 · 금액 · 관리항목 · 코스트센터 (각각 가져올 곳)
        - 매달 프로그램이 전표를 만들지 않고 알리는 경우 (처음 보는 파일 행, 이름으로 못 찾은 코드 등)
        - 필요한 API
    - 작업 폴더에 `전표틀.md` 로 남긴다. 형식은 다음 단계(전표 틀 형식 설계)에서 확정한다.
    - 법인마다 정의서를 [api/정의서.md](../../api/정의서.md) 형식으로 만들어 작업 폴더에 `정의서_<법인 이름>.json` 으로 남긴다.
        - 맨 앞 `목적`은 `참고자료.md`의 목적을 그대로 넣는다.
        - 줄은 행 유형의 계정·차대·매달로 채운다.
        - 관리항목은 6-2에서 고정으로 정한 것만 넣는다.
    - 다음 단계는 아직 정하지 않았다. 끝나면 무엇이 남았는지 알리고 멈춘다.

## 현업에게 묻는 것

- 이 파일로 만들 법인 (여러 개 가능)
- 전표일자를 정하는 방법, 적요에서 매달 바뀌는 부분
- 행 유형마다 생성 규칙 추측과 매달 생기는지가 맞는지 (아니면 왜 그렇게 썼는지)
- 고정으로 정한 관리항목이 바뀐 적이 있거나 바뀔 수 있는지
- 행 유형마다 금액·관리항목·코스트센터를 가져올 곳이 맞는지 (아니면 가져올 곳 선택지)

## 쓰는 API

- API는 이 명령 하나로만 부른다: `python -X utf8 "${CLAUDE_PLUGIN_ROOT}/api/call.py" <짧은 경로> <요청 파일>`

부르는 법은 [api/호출방법.md](../../api/호출방법.md)에 있다 (개발서버, 개발 DB).

| 언제 | API |
| --- | --- |
| 참고 전표 가져오기 | 전표 조회 → [api/전표조회.md](../../api/전표조회.md) |
| 1. 법인 | API 없음 → [api/법인.md](../../api/법인.md) 표 |
| 2. 작성부서 (다른 부서를 고를 때만) | 작성부서 조회 → [api/작성부서.md](../../api/작성부서.md) |
| 5. 계정 (지금 쓸 수 있는지, 관리항목·코스트센터·외화 여부) | 계정과목 조회 → [api/계정과목.md](../../api/계정과목.md) |
| 6-2. 관리항목 (값 확인·찾기) | 관리항목 값 조회 → [api/관리항목값.md](../../api/관리항목값.md) |
| 6-3. 코스트센터 (코드 찾기, 원가구분) | 코스트센터 조회 → [api/코스트센터.md](../../api/코스트센터.md) |

- 이 API들로 알 수 없는 것(예: 줄을 나누는 기준에 필요한 정보, 아직 지원하지 않는 관리항목)은 "필요한 API"로 기록하고 넘어간다.

## 대화 원칙

- 한글, 쉬운 말로 한다. 한 번에 하나씩 묻는다.
- 코드가 있는 값(법인, 작성부서, 계정, 코스트센터, 거래처, 관리항목 값 등)은 이름 뒤에 코드를 괄호로 함께 쓴다 (예: ○○ (코드)). 이름이 비슷한 값이 있어도 현업이 코드로 확인할 수 있다.
- 방법을 고르게 할 때는 보기를 예시로 보여 주고, 다른 방법도 말할 수 있게 묻는다.
    > 예를 들면 이런 방법이 있어요. 여기 없는 방법이면 편하게 말씀해 주세요.
- 전표 생성 API는 부르지 않는다.
- 명령을 실행할 때 붙이는 설명은 현업이 알아볼 수 있는 쉬운 한국어로 쓴다 (예: "지난 전표를 가져와요", "거래처 목록을 조회해요").
- 플러그인 안내 파일은 `cat` 같은 명령 대신 읽기 도구로 읽는다.
