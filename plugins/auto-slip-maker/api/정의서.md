# 정의서

> 정의서 등록 API는 아직 없다. 지금은 작업 폴더에 파일로 남긴다.

## 하는 일

- 반복 전표 하나(법인 하나)에 정의서가 하나 있다.
- 서버에 등록하고 승인받은 정의서로만 운영에서 전표 생성 API를 부를 수 있다 (예정). 정의서를 고치면 다시 승인받는다.
- 생성 요청이 올 때마다 서버가 요청이 정의서대로인지 검사한다.
- 값을 어떻게 만드는지(파일 위치, 계산 방법)는 적지 않는다. 그건 `전표틀.md` 에 있다.

## 형식

```json
{
  "정의서ID": null,
  "버전": null,
  "이름": "(목록에서 알아볼 이름)",
  "목적": "(무엇 때문에 쓰는 전표인지 한 줄)",
  "법인": "(법인 코드)",
  "사용자": "$USER",
  "작성부서": "(작성부서 코드)",
  "줄": [
    { "계정": "(계정 코드)", "차대": "차변", "생성": "매번", "관리항목": { "(관리항목 코드)": "(값)" } },
    { "계정": "(계정 코드)", "차대": "대변", "생성": "선택", "관리항목": {} }
  ]
}
```

| 칸 | 뜻 |
| --- | --- |
| 정의서ID, 버전 | 서버에 등록할 때 정해진다. 파일에는 `null` 로 둔다 |
| 이름 | 정의서 목록에서 알아볼 이름 |
| 목적 | 무엇 때문에 쓰는 전표인지 한 줄 (틀 잡기에서 받음). 자동화 요청 하나의 범위이고, 승인자가 계정이 맞는지 판단하는 기준이다. 서버가 검사하지는 않는다 |
| 법인, 작성부서 | 코드 |
| 사용자 | `$USER` 로 적는다. 등록할 때 작성자 ID로 바뀐다 (작성자 ID는 파일에 쓰지 않는다) |
| 줄 | 행 유형(계정·차대)마다 하나 |
| 줄.차대 | `차변` / `대변` |
| 줄.생성 | `매번`: 이 계정·차대 줄이 1줄 이상 있어야 한다. `선택`: 없어도 된다. 몇 줄인지는 보지 않는다 |
| 줄.관리항목 | 고정으로 정한 관리항목만 `{코드: 값}` 으로 적는다. 달라지는 값과 비워 두는 칸은 적지 않는다 |

## 서버가 검사하는 것 (예정)

| 거부한다 | 보지 않는다 |
| --- | --- |
| 승인된 정의서ID·버전이 아니다 | 전표일자, 금액, 적요 |
| 사용자, 법인, 작성부서가 정의서와 다르다 | 코스트센터 |
| 정의서에 없는 계정·차대 줄이 있다 | 정의서에 적지 않은 관리항목 |
| `매번` 줄이 없다 | |
| 적힌 관리항목의 값이 다르다 | |

- 코드를 지금 쓸 수 있는지, 필수 관리항목이 빠졌는지, 차대 합계가 맞는지는 전표 생성 API가 따로 본다.
